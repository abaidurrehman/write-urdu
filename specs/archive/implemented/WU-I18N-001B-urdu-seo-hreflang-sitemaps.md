# WU-I18N-001B — Urdu SEO, Hreflang, Canonicals & Sitemaps

**Parent:** `WU-I18N-001`  
**Depends on:** `WU-I18N-001A`  
**Status:** Planned — Slice B  
**Primary owners:** `seo.config.js`, locale metadata registry, SEO generator/checker

## 1. Goal

Make each Phase 1 `/urdu/*` page a technically correct, independently indexable Urdu document while preserving the established English URL as the English search owner.

This slice is complete only when the search contract is visible in initial HTML and deterministically validated in the repository.

## 2. Canonical contract

Every locale page canonicalizes to itself.

Examples:

```text
https://write-urdu.com/
  canonical -> https://write-urdu.com/

https://write-urdu.com/urdu/
  canonical -> https://write-urdu.com/urdu/

https://write-urdu.com/urdu-keyboard
  canonical -> https://write-urdu.com/urdu-keyboard

https://write-urdu.com/urdu/urdu-keyboard
  canonical -> https://write-urdu.com/urdu/urdu-keyboard
```

Never use the English URL as the canonical of the Urdu page.

## 3. Hreflang contract

For every Phase 1 pair, emit reciprocal alternate links in initial HTML.

English page:

```html
<link rel="alternate" hreflang="en" href="https://write-urdu.com/urdu-keyboard">
<link rel="alternate" hreflang="ur" href="https://write-urdu.com/urdu/urdu-keyboard">
<link rel="alternate" hreflang="x-default" href="https://write-urdu.com/urdu-keyboard">
```

Urdu page:

```html
<link rel="alternate" hreflang="en" href="https://write-urdu.com/urdu-keyboard">
<link rel="alternate" hreflang="ur" href="https://write-urdu.com/urdu/urdu-keyboard">
<link rel="alternate" hreflang="x-default" href="https://write-urdu.com/urdu-keyboard">
```

Rules:

- pairs are reciprocal;
- `x-default` points to the established English/default route;
- use `ur`, not `ur-PK`, for the general locale;
- do not emit Urdu hreflang for an unregistered/nonexistent Urdu page;
- no JavaScript-only hreflang injection.

## 4. Localized metadata source

Extend the SEO/locale registry so Urdu search metadata is reviewed and explicit, not generated by literal translation at deploy time.

For each Phase 1 route store at minimum:

```text
Urdu title
Urdu search description
Urdu H1
Urdu lede/answer summary
optional localized schema name/description
last reviewed date
```

The English metadata in `seo.config.js` remains authoritative for English pages.

Avoid duplicating route indexability and priority logic in multiple registries. Compose locale metadata with the canonical page record.

## 5. Metadata quality rules

Urdu titles and descriptions should explain the task naturally in Urdu while preserving useful brand/product terms only where they help comprehension.

Prefer:

```text
آن لائن اردو لکھیں
اردو کی بورڈ
بولیں اور اردو میں لکھیں
انگریزی حروف میں اردو لکھیں
```

over awkward literal technical phrasing.

Do not stuff the same phrase repeatedly into title, H1, description and body.

Do not make `Roman Urdu` or `transliteration` the primary visible wording unless the page genuinely needs the concept explained.

## 6. HTML language and direction

Urdu generated pages must ship:

```html
<html lang="ur" dir="rtl">
```

English pages remain:

```html
<html lang="en">
```

Do not rely on CSS direction alone.

Specific embedded content may use `lang="en" dir="ltr"` when appropriate, such as code snippets, URLs, email addresses or English examples.

## 7. Open Graph / social metadata

Urdu pages must have locale-correct social metadata in initial HTML:

```text
og:title        Urdu page title
og:description  Urdu description
og:url          Urdu canonical URL
og:locale       ur_PK is acceptable only as social-platform locale syntax if required
```

Keep canonical/search locale semantics separate from Open Graph's platform-specific locale identifiers.

Where the existing social preview image remains appropriate, it may be reused. Do not block Phase 1 on creating eight new images unless the English artwork itself contains misleading English-only text.

## 8. Structured data

Existing schema types remain owned by the underlying product route.

Examples:

```text
WebApplication remains WebApplication
FAQPage remains FAQPage
Article remains Article
```

For Urdu pages:

- schema URL points to Urdu canonical;
- human-readable `name`, `headline`, `description` should match the Urdu document when emitted;
- publisher/organization identity remains the same Write Urdu entity;
- do not duplicate English and Urdu FAQ questions in one schema block unless both are visibly present;
- do not claim language-specific ratings, users or capabilities that are not evidenced.

Use `inLanguage: "ur"` where valid for the emitted schema type.

English schema may use/retain `inLanguage: "en"` where appropriate.

## 9. Sitemap architecture

Preferred Phase 1 structure:

```text
/sitemap.xml       sitemap index
/sitemap-main.xml  established English indexable URLs
/sitemap-urdu.xml  registered Urdu indexable URLs
```

If changing `/sitemap.xml` into an index creates unnecessary deployment risk, an interim single URL-set is acceptable only if:

- both locale URL sets are present;
- generation is deterministic;
- hreflang alternates can be validated separately;
- Search Console can still isolate `/urdu/` performance through page filtering.

Do not manually maintain an Urdu sitemap.

## 10. Sitemap locale inclusion rules

A page enters `sitemap-urdu.xml` only when all are true:

1. underlying product route is indexable;
2. locale registry marks Urdu as launched/indexable;
3. generated Urdu file exists;
4. localized title/H1/description pass validation;
5. page is not a user-generated share artifact or account utility.

Phase 1 expected count: **8 Urdu URLs**.

Full rollout count is determined by the current indexable public registry at implementation time; do not hard-code an assumed 30 forever.

## 11. Robots and crawl policy

`robots.txt` continues to allow normal search crawlers to access `/urdu/` under the existing crawler policy.

Do not add a special Urdu user-agent section.

Ensure generated locale files are not accidentally blocked by:

- `/urdu/` disallow rules;
- broad `/tools/` rules;
- build artifact exclusions;
- Cloudflare route protections.

## 12. Redirect and duplicate rules

Required outcomes:

```text
/urdu/urdu-keyboard.html -> 301 -> /urdu/urdu-keyboard
/urdu/urdu-keyboard/     -> canonical clean route with at most one normalization redirect
```

Avoid:

```text
/urdu/urdu-keyboard -> /urdu-keyboard
/urdu/ -> /
```

unless explicitly retiring the locale in a future rollback.

No redirect chain should be introduced between protocol/host normalization and locale clean-URL normalization.

## 13. Internal-link contract

On a launched Urdu page:

- links to another Phase 1 route should use its Urdu counterpart;
- language switch points to the exact English counterpart;
- links to nonlocalized routes may remain English destinations temporarily rather than inventing thin Urdu URLs;
- no important Urdu page should be discoverable only through the sitemap.

Add at least one crawlable entry to `/urdu/` from the English site-wide shell or locale control.

## 14. SEO checker extensions

Extend `scripts/check-seo.js`, `scripts/sync-static-search-metadata.js` or a focused locale checker so CI verifies:

### Per Urdu page

- file exists;
- `lang=ur`;
- `dir=rtl`;
- self canonical;
- reciprocal `en`, `ur`, `x-default` links;
- title/description match registry;
- one meaningful H1;
- no `noindex` on launched corpus;
- OG URL matches canonical;
- JSON-LD URL/inLanguage match when schema exists;
- no English canonical leak.

### Pair integrity

For every launched Urdu route:

- English source route exists;
- English page points to Urdu alternate;
- Urdu page points back to English;
- both URLs are unique;
- no two Urdu pages canonicalize to the same route.

### Sitemap integrity

- exact launched Urdu set is present;
- no unlaunched/noindex Urdu route is present;
- sitemap URLs use canonical hostname and clean URLs;
- all sitemap Urdu URLs resolve to generated sources locally.

## 15. Homepage-specific guardrail

The English homepage is a protected high-value acquisition owner. Adding `/urdu/` must not rewrite or weaken its established English-to-Urdu search metadata.

The Urdu homepage gets its own reviewed Urdu title/H1/description and reciprocal hreflang, while `/` retains its current search-intent experiment.

Do not combine both languages into one title to avoid creating the Urdu page.

## 16. Search Console launch checklist

After production release:

- submit/refresh sitemap(s);
- inspect `/urdu/` and at least three representative nested Urdu URLs;
- verify Google sees the self canonical rather than selecting English as canonical;
- request indexing for the eight Phase 1 pages in a measured rollout, not repeated daily submission;
- monitor Pages and Queries filtered to `/urdu/`;
- record discovered Urdu-script query families.

Search Console operations are deployment tasks and should be documented; they are not simulated by tests.

## 17. Rollback behavior

If Phase 1 has a severe technical issue:

- remove Urdu pages from sitemap generation;
- fix the generated pages;
- prefer temporary `noindex` only when a page must remain user-accessible during repair;
- do not mass-redirect Urdu pages to unrelated English pages as a first response.

Once search engines have indexed `/urdu/*`, URL retirement requires explicit SEO migration planning.

## 18. Acceptance criteria

- [ ] All eight Urdu pages self-canonicalize.
- [ ] English/Urdu hreflang pairs are reciprocal.
- [ ] `x-default` points to the English/default route.
- [ ] Urdu metadata is reviewed and registry-backed.
- [ ] `lang=ur` / `dir=rtl` are present in initial HTML.
- [ ] Schema URLs/language match locale where schema exists.
- [ ] Urdu sitemap contains exactly launched indexable Urdu routes.
- [ ] `.html` variants normalize to clean Urdu canonicals without chains.
- [ ] English homepage and other English canonical metadata remain unchanged except for reciprocal alternate links.
- [ ] SEO checks fail on missing/incorrect locale metadata or pair integrity.

## 19. Verification

```text
npm run locale:generate
npm run locale:check
npm run seo:generate
npm run seo:check
npm test
```

Do not begin broad Phase 2 localization while canonical/hreflang/sitemap integrity is unresolved.
