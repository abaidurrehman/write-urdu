# WU-CARD-GALLERY-001A — Social Background Collection Expansion

**Status:** Planned / founder-approved 2026-09-13  
**Parent:** `WU-CARD-GALLERY-001`  
**Related:** `WU-CARD-CONTENT-001`, `WU-CARD-CONTENT-001A`, `WU-CARD-RETENTION-001`, `WU-CARD-RETENTION-001A`, `/urdu-card-studio`, `/urdu-card-gallery`, `/urdu-cards`  
**Area:** Card creation / social sharing / visual design system  
**Core promise:** Expand the shared Write Urdu card background collection with original, receiver-quality designs intentionally matched to the recurring social-content jobs that drive repeat use.

---

## 1. Product goal

The current card ecosystem has proven that good-looking backgrounds materially improve the appeal of `/urdu-cards` and Card Studio. The next step is not to create arbitrary decorative variants. It is to expand the shared background registry around the recurring content families identified for retention:

- morning / Subah Bakhair;
- evening / reflection;
- night / Shab Bakhair;
- Jumma / Friday;
- dua / faith / gratitude;
- hope / motivation / life reflection;
- family / parents / friendship;
- love / affection;
- original short poetry / emotional lines;
- Pakistan / cultural pride;
- Ramadan / Eid seasonal moments.

The collection should help a user feel that the design already suits the message before they touch any advanced controls.

The product loop is:

`prepared or user-written Urdu → visually appropriate background → readable finished card → share / edit`

This child extends the existing shared background system. It does **not** create a second design engine.

## 2. Relationship to existing owners

### `WU-CARD-GALLERY-001`
Owns the background-first browse/compare experience and the shared background-registry architecture.

### `WU-CARD-CONTENT-001` / `001A`
Own the ready-made card content and recurring prepared-text library. This child supplies visual families those messages can use.

### `WU-CARD-RETENTION-001A`
Owns the one contextual homepage card. The homepage must consume approved backgrounds from the same shared registry; it must not create homepage-only art.

### Card Studio
Remains the authoritative advanced editor/export destination.

Hard rule: **one shared background registry, one set of stable IDs, one rendering/export architecture.**

## 3. Design principles

### 3.1 Receiver-first quality

The final image received on WhatsApp, Facebook, Instagram, Messages or another app is the quality bar.

Every new design must remain:

- readable on a normal phone;
- recognisable after platform compression;
- visually intentional without requiring editor controls;
- calm enough for Urdu text;
- suitable for real social sharing rather than only attractive as a thumbnail.

### 3.2 Urdu text owns the centre of attention

Decorative art must frame or support the text, not compete with it.

Each design needs a deliberate text-safe region.

Avoid:

- busy high-frequency detail behind text;
- decorative text baked into the background;
- pseudo-Arabic/Urdu glyph decoration that can be mistaken for words;
- faces or focal objects directly behind the primary text area;
- low-contrast ornamental textures across the entire canvas.

### 3.3 Original design language

External social-media research informs **content jobs and broad visual motifs**, not asset copying.

Do not reproduce or trace Pinterest, Instagram, Reddit, Canva, competitor or stock designs.

New Write Urdu art must be original.

### 3.4 Distinct families, not colour swaps

A design does not count as a new family merely because hue, border colour or gradient stops changed.

Each family must differ meaningfully in composition, motif, mood or visual language.

## 5. Asset production strategy

Use the simplest original-production method that preserves quality.

### Preferred for deterministic, maintainable designs

- SVG backgrounds created as original vector compositions;
- CSS/vector-generated geometry where export parity is preserved;
- lightweight WebP derivatives for gallery thumbnails if useful.

### Appropriate for richer atmospheric art

- original raster artwork generated/created specifically for Write Urdu;
- optimized WebP source + thumbnail;
- no embedded text;
- preserve source provenance internally.

### Do not

- hotlink external images;
- scrape social-media assets;
- copy stock-preview images;
- commit watermarked art;
- embed third-party remote runtime image dependencies;
- ship temporary placeholders as production backgrounds.

If an implementation agent cannot create a requested painterly/raster asset to the required quality, it should complete the metadata/quality infrastructure and ship only the strong original vector-capable designs rather than fake abundance.

## 6. Registry contract

Every new background must use the canonical shared background registry and include stable metadata consistent with the current architecture.

Minimum fields:

```js
{
  id,
  name,
  nameUr,
  category,
  src,
  thumbnailSrc,
  textColor,
  overlayColor,
  overlayOpacity,
  safeArea,
  textCapacity,
  preferredAlign,
  goodFor
}
```

### New metadata guidance

`goodFor` should use bounded tags such as:

```text
morning
night
jumma
dua
reflection
motivation
family
friendship
love
poetry
self-respect
pakistan
ramadan
eid
social
```

Do not invent free-form tags per asset.

`textCapacity` must reflect actual visual testing, not assumption.

`safeArea` must be measured for the composition.

## 7. Stable ID policy

Existing background IDs are compatibility contracts.

- never rename an existing ID merely for aesthetics;
- never reuse a retired ID for unrelated art;
- new IDs should be concise, semantic and stable;
- Card Studio projects/handoffs must continue resolving all shipped IDs.

Examples of acceptable new IDs:

```text
soft-sunrise-garden
moon-quiet-sky
jumma-ivory-geometry
warm-paper-reflection
minimal-cream-poetry
quiet-blue-distance
ajrak-modern-frame
```

## 8. Text-safe-area acceptance

Each background must be tested with canonical Urdu fixtures:

### Short

1–2 lines, e.g. greeting or short dua.

### Medium

3–4 lines, typical prepared message.

### Long

6–8 lines, only for designs claiming `textCapacity: long`.

Rules:

- no clipping;
- no collision with focal decoration;
- no misleading gallery preview that appears safe but exports badly;
- Nastaliq line-height must be visually comfortable;
- mixed Urdu/Latin/numbers should not break the composition.

Designs can legitimately be `short` or `medium`; not every background must support long text.

---

## 9. Contrast and overlay rules

Registry defaults should make every background usable before manual editing.

- text colour must meet strong practical visual contrast;
- overlay opacity should be as low as possible while preserving readability;
- avoid generic heavy black overlays that destroy the artwork;
- text shadow may support legibility but must not become the primary contrast strategy;
- light and dark variants count as separate designs only when composition/use-case meaningfully differs.

---

## 10. Homepage relationship

`WU-CARD-RETENTION-001A` may select only backgrounds marked/validated for the relevant recurring context.

The homepage does **not** get a special design set.

Example:

```text
morning context → cards using goodFor: morning/dua/motivation
Friday override → cards using goodFor: jumma/dua
night context → cards using goodFor: night/dua/reflection
```

The homepage still shows exactly one card and two actions.

This child must not add a background picker, carousel or design selector to the homepage.

---

## 11. Prepared-text relationship

`WU-CARD-CONTENT-001A` should pair prepared messages intentionally with these designs.

Do not produce Cartesian-product abundance.

A prepared message may have:

- one default approved background;
- optionally 2–3 approved alternates;
- context tags that make later deterministic matching possible.

The gallery can expose more designs when the user chooses to customize, but ready-made cards should remain curated pairings.

---

## 12. Performance budgets

Rich art must not degrade the card surfaces.

Requirements:

- thumbnails for gallery/browse surfaces where full assets are heavy;
- lazy-load offscreen raster art;
- no loading all full-resolution backgrounds on first viewport;
- preserve fast typing in `/urdu-card-gallery`;
- no full-canvas renderer per gallery tile;
- avoid large uncompressed PNG/JPEG sources when optimized WebP/SVG is viable;
- do not pre-cache an unbounded art library in the service worker.

Every added asset needs a deliberate size review.

---

## 13. Accessibility

Background art is decorative.

- do not create noisy alt text for decorative images;
- actual Urdu message remains DOM text in galleries;
- names/categories remain accessible to controls;
- contrast must be usable by real readers, not only screenshot reviewers;
- no information should depend exclusively on colour.

---

## 14. SEO

This work expands product quality. It does **not** justify new indexable pages by itself.

Do not create routes such as:

```text
/urdu-card-backgrounds/morning
/urdu-card-backgrounds/jumma
/urdu-card-backgrounds/poetry
```

without separate evidence/SEO ownership.

Existing `/urdu-card-studio`, `/urdu-card-gallery` and `/urdu-cards` remain the product surfaces.

---

## 15. Telemetry

Background IDs are controlled public product metadata and can be used in bounded telemetry where the existing telemetry contract permits.

Never log:

- user-entered Urdu;
- prepared message text as raw telemetry;
- rendered images;
- arbitrary image URLs;
- external asset provenance strings.

Do not add telemetry merely to count every render.

Useful questions include:

- which background IDs are selected;
- which background families lead to Card Studio handoff;
- which ready-made card IDs are shared;
- whether new designs improve completion over the prior collection.

Reuse approved event systems.

Do not automatically continue generating more backgrounds.

## 17. Acceptance gates

The child is successful only when:

- [ ] New art is original and locally owned/controlled.
- [ ] No external social/stock asset is copied or hotlinked.
- [ ] All new designs come from the shared background registry.
- [ ] Existing IDs continue working unchanged.
- [ ] Every new design has validated safe-area metadata.
- [ ] Every new design has tested short/medium capacity and honest long-text capability.
- [ ] Urdu remains readable on real mobile-sized output.
- [ ] Default text colour/overlay settings are usable without manual repair.
- [ ] Gallery previews remain lightweight and responsive.
- [ ] Card Studio can load/export every new design.
- [ ] Ready-made cards can pair with the designs without duplicating renderer logic.
- [ ] Homepage contextual card can consume eligible designs without adding homepage controls.
- [ ] No new thin SEO routes are created.
- [ ] No private text enters telemetry.
- [ ] Asset-size/performance review passes before merge.
- [ ] Receiver-quality screenshots/exports are manually reviewed.

## 19. Definition of done

Write Urdu has a broader but still curated background system whose new designs clearly serve the recurring social messages users are most likely to share. Morning, night, Jumma, dua, poetry, emotional, family, cultural and seasonal content can each feel intentionally designed, while all three card surfaces and the homepage contextual card continue to reuse one fast, stable, browser-first visual architecture.
