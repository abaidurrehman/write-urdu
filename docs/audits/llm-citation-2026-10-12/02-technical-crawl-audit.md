## 1. Architecture summary (Verified, repo)

- **Framework:** none. Hand-authored static HTML per route (`index.html`, `urdu-keyboard.html`, `tools/*.html`, `urdu/*.html`), vanilla JS in `js/`, TinyMCE for `/urdu-editor`. Cloudflare Pages hosting; `_redirects` handles `.html` → extensionless and trailing-slash normalisation.
- **SEO source of truth:** `seo.config.js` (titles, descriptions, H1, canonical, indexability, schema types, lastmod) → `scripts/generate-seo-files.js` (robots, sitemap), `scripts/sync-static-search-metadata.js` (heads), `scripts/sync-static-seo-graph.js` (JSON-LD), `scripts/sync-static-shell.js` (static nav/footer), `scripts/sync-static-collection-content.js` (static collection HTML). Checks: `npm run seo:check`, `seo:graph:check`, `shell:check`, `collections:check`.
- **Urdu locale:** `/urdu/…` siblings generated by `scripts/generate-urdu-locale.js` with reciprocal `hreflang` (en/ur/x-default) — 11 Urdu routes.
- **Rendering strategy:** static-first. Title, meta description, canonical, robots, H1, explanatory copy, FAQ and JSON-LD are **in the initial HTML** for all indexable routes. JS adds editors, canvas, filtering, and on some pages the **collection content** (see §5).

## 2. robots.txt, crawler controls and llms.txt

### 2.1 robots.txt (Verified, repo — `robots.txt`, generated)

```
User-agent: *            Allow: /
Googlebot / OAI-SearchBot / PerplexityBot / Bingbot / ClaudeBot / Claude-SearchBot   Allow: /
GPTBot                   Disallow: /
Google-Extended          Allow: /
Sitemap: https://write-urdu.com/sitemap.xml

```

What each control does and does **not** establish:

| Control | Effect | Does not establish |
| --- | --- | --- |
| `Googlebot` allowed | Google Search indexing; also the only crawler that feeds **AI Overviews / AI Mode** (they draw from Google's search index) | That AI Overviews will cite any page |
| `Google-Extended` allowed | Permits use of content for Gemini model training/grounding beyond Search | Has **no effect** on Search ranking or AI Overviews eligibility |
| `OAI-SearchBot` allowed | Eligible to appear/cite in **ChatGPT search** | Training use |
| `GPTBot` disallowed | Opts out of OpenAI **model training** crawling | Does **not** block ChatGPT search citations (that is OAI-SearchBot) — correctly documented in `docs/SEO-CRAWLER-POLICY.md` |
| `ClaudeBot` allowed | Anthropic training crawler | — |
| `Claude-SearchBot` allowed | Anthropic search-quality indexing for Claude web search | Citation by Claude |
| `PerplexityBot` allowed | Perplexity's index | Citation |
| user-triggered fetchers (`ChatGPT-User`, `Claude-User`, `Perplexity-User`) | Not named; covered by `User-agent: * Allow: /` | — |

**Finding T-1 (no blocker):** robots policy is correct and well-documented. No change recommended. robots.txt cannot override a Cloudflare WAF/Bot-Fight rule; whether Cloudflare challenges `OAI-SearchBot`, `PerplexityBot` or `Claude-SearchBot` is **Unverified** (requires Cloudflare dashboard → Security → Events filtered by those user agents, or `curl -A` from an unblocked network — see §8).

## 3. Sitemap, canonicals, hosts and redirects

### 3.1 sitemap.xml (Verified, repo)
50 URLs, all apex `https://write-urdu.com`, matching `seo.config.js` indexable routes plus Urdu locale routes. Noindex utilities (`/feedback`, `/sign-in`, `/write-urdu-search`, preview translator/dictionary tools) are correctly excluded.

**Finding T-3 (P3, low):** `lastmod` values are hand-set in `seo.config.js` and lag shipped changes (e.g. `/` = `2026-08-19`, `/urdu-card-studio` = `2026-08-17` although both changed on 2026-10-10/11 per `git log`). JSON-LD `dateModified` uses the same value. Google says it uses `lastmod` only when it is consistently accurate; stale values are harmless but waste the signal. Optional fix: derive from `git log -1 --format=%cs -- <file>` in `generate-seo-files.js`.

### 3.2 Canonicals (Verified, repo)
Every indexable route has an exact apex self-canonical in raw HTML; canonical, `og:url`, sitemap and JSON-LD `@id`/`url` all agree on apex. `_headers` adds `X-Robots-Tag: noindex` on `*.pages.dev` aliases. No conflicts found.

### 3.3 Host normalisation — **Finding T-4 (P0, external config, Unverified today)**
- 2026-10-04 live check: HTTPS `www` returned **200 duplicates** instead of 301 to apex; HTTP `www` → HTTPS `www` (extra hop); unknown `www` paths 404 rather than redirect (`A0-A1-BASELINE.md`).
- GSC: `www` URLs earned **105,172 impressions / 4,946 clicks (19.1% of clicks)**; `www.write-urdu.com/` alone 86,686 impressions.
- **New AI-retrieval evidence (this audit):** a Claude web search on 2026-10-12 for `"write-urdu.com" urdu editor` returned `https://www.write-urdu.com/write-urdu-features`, `/write-urdu-privacy`, `/write-urdu-sitemap` and summarised **obsolete content** ("Switch to Urdu HTML editor", "WhatsApp it", terms limiting downloads to "personal, non-commercial use") — wording that no longer exists in the repo. AI search indexes are holding stale `www` copies; until `www` 301s to apex they have no strong signal to replace them.
- No repository change can fix this (`_redirects` cannot match hosts — see `docs/CLOUDFLARE-CANONICAL-HOST.md`). The rule is already specified in `A0-A1-BASELINE.md` ("Required repair"). Blocked on a Cloudflare token with `Zone > Single Redirect > Edit` (`specs/WU-SEO-CTR-001A-IMPLEMENTATION-CHECKLIST.md` line 81).

### 3.4 Path redirects (Verified, repo)
`_redirects` 301s every legacy `.html` and trailing-slash variant to the extensionless canonical, including `/urdu/…` locale paths. 2026-10-04 live check confirmed this on six priority routes.

Answers to the required questions:

- **Can a retrieval system identify each page's purpose without JS?** Yes for every priority page: title, meta description, H1, a lede and JSON-LD are server-delivered.
- **Can it extract the main explanation without JS?** Yes for typing, Roman, keyboard, InPage, phrases, practice, fonts, photo guide, Card Studio. **No** for the ready-made content that the `/urdu-cards` and `/urdu-whatsapp-status-maker` titles promise.
- **Is critical content hidden in the editor UI?** On Card Studio the static HTML begins with UI-label headings (`<h2>Canvas</h2>`, `<h2>Template</h2>`, `<h2>Content</h2>`, `Text style`, `Layout`, `Background`, `Branding` — `urdu-card-studio.html:113,119,128…`) before the explanatory `<h2>Create Urdu cards and quote images online</h2>`. Extractors that weight early headings see control labels first. Low severity; content still extractable.
- **Heading structure:** one H1 per page everywhere (Verified for all 60 HTML routes). Keyboard page uses an empty `<h4>` and an `<h4>How to use the Urdu keyboard</h4>` before the H2s — cosmetic.
- **Fragmented passages:** InPage and Roman pages are clean, short H2/H3 + paragraph blocks — good passage units. Homepage key steps are an 11-item `<ul>` mixing instructions with links ("Read the Urdu FAQ for clear answers…") — dilutes the how-to passage.
- **Do links and canonical signals agree?** Canonicals yes. Anchor text **no** in 8 places (see §7 / file 07 A-4).

**Finding T-5 (P2): JS-only collection content on two indexable pages.** `WU-SEO-CRAWL-001D` (archived as complete) explicitly scoped `/urdu-whatsapp-status-maker` as a "direct creation workspace" whose "use-case guidance is already in source HTML" (`specs/archive/implemented/WU-SEO-CRAWL-001D-static-collection-content.md:78`). Today, however, the status page leads with a ready-made status library (`data-whatsapp-status-grid`, first committed in `b4fed53`, 2026-09-17) and `/urdu-cards` (indexed under P0.9, 2026-09-13) is a browse-only library — and both libraries render only in JS. The static-collection classification no longer matches the pages' own promise ("Browse ready-made Urdu WhatsApp Status text…" in the meta description).

**Finding T-6 (P3): no `<main>` landmark in raw HTML** on `/`, `/urdu-keyboard`, `/urdu-editor`, `/urdu/`, `/urdu/urdu-keyboard`, `/urdu/urdu-editor`. `site-header.js:117-131` assigns `role="main"` at runtime. Readability-style extractors used by some AI fetchers look for `<main>`/`<article>`; without JS they fall back to heuristics that may include nav text. Low-risk fix but touches the three highest-traffic templates — CSS must be verified.

## 6. Page-specific technical notes

- **InPage converter** — conversion is browser-local (`js/inpage-unicode-core.js`, no network call in `js/inpage-unicode-converter.js`; telemetry sends only `tool_handoff {target_route}` at line 229). The visible FAQ answer "Does WriteUrdu upload my text? — *Your pasted text is used for the conversion. See Privacy…*" (`tools/inpage-unicode-converter.html:140`) **under-claims** the actual privacy property. This wording is deliberate: `scripts/public-language-firewall.js:60` rewrote the earlier "No. This converter does not send the source…" answer, and its `defensiveOutsidePrivacy` patterns (lines ~144-154: "processed in your browser", "stays on your device", "without uploading", "paid API") fail `npm run language:check` on any public page except Privacy. Changing it is an owner decision, not a bug fix (file 07 A-20). The "Load example" before/after exists only in JS (`js/inpage-unicode-converter.js:196-201`).
- **Voice typing** — uses the browser Web Speech API (`js/voice-input-core.js:20`, `SpeechRecognition || webkitSpeechRecognition`) with `lang='ur-PK'` (`js/voice-input-core.js:67`). The page shows a runtime "Checking support" state; no static compatibility or permission-recovery text exists on the owner page (details live only in `/write-urdu-privacy`).
- **Card Studio** — duplicated phrase in static copy: "Your background stays available while you work while you design." (`urdu-card-studio.html`, "Use your own background privately").

## 8. Production checks to run (cannot be run from this environment)

```bash
# 1. Host consolidation (expect 301 → https://write-urdu.com/<same path>)
for u in https://www.write-urdu.com/ http://www.write-urdu.com/urdu-keyboard https://www.write-urdu.com/does-not-exist; do curl -sI "$u" | sed -n '1p;/^location/Ip'; done
# 2. AI crawler access through Cloudflare (expect 200, not 403/challenge)
for ua in "OAI-SearchBot/1.0; +https://openai.com/searchbot" "PerplexityBot/1.0" "Claude-SearchBot/1.0" "Mozilla/5.0 (compatible; bingbot/2.0)"; do
  echo "$ua"; curl -s -o /dev/null -w '%{http_code}\n' -A "$ua" https://write-urdu.com/tools/inpage-unicode-converter; done
# 3. Reachability of discovery files
for p in robots.txt llms.txt sitemap.xml sitemap-community.xml .well-known/security.txt; do curl -s -o /dev/null -w "$p %{http_code}\n" https://write-urdu.com/$p; done
# 4. X-Robots-Tag on priority pages (expect none)
curl -sI https://write-urdu.com/ | grep -i x-robots
```

A user-agent spoof only shows UA-based rules; Cloudflare "Verified Bots" decisions use reverse-DNS/IP and must be confirmed in Security → Events.
